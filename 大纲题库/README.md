# 大纲题库

按教材单元组织的题，每个知识点 3 道。和另外两个库分工不同：

| 库 | 装什么 | 怎么来 |
|---|---|---|
| `数学/语文/英语错题库` | 她**做错过的**原题 | 拍照采集、考试卷 |
| `题库/variants.json` | 错题的**变式** | 由错题派生，用来检验有没有掌握 |
| **`大纲题库/题库.json`** | **按教材进度该会的题** | 按课标和教材自己出，不依赖她错没错 |

三个库互不覆盖。大纲题库解决的是「她还没错过、但该会的」那部分——目前是空白。

## 数据结构

```json
{
  "版本": 1,
  "单元": [{"科":"数","年级":"五上","单元":"U1","名称":"小数乘法","周次":"9 月上"}],
  "知识点": [{"id":"M-U1-01","科":"数","单元":"U1","名称":"小数乘整数","课标":"数与代数"}],
  "题目": [
    {
      "id": "Q-M-U1-01-1",
      "知识点": ["M-U1-01"],          // 数组，综合题填多个
      "难度": 1,
      "类型": "choice",
      "题干": "一支笔 2.5 元，买 3 支一共多少元？",
      "选项": ["7.5 元", "6.5 元", "7.05 元", "75 元"],
      "答案": 0,                        // choice 是下标（从 0 开始）；number 是数值
      "提示": "先按 25×3 算，再点小数点。",
      "解析": "25×3=75。2.5 是一位小数，积也点一位：7.5。"
    }
  ]
}
```

### 难度怎么分

| 难度 | 含义 | 例子 |
|---|---|---|
| 1 | 概念直用，一步到位 | 2.5 × 3 = ? |
| 2 | 需要两步，或要辨析 | 0.25 × 12（要先算 25×12 再点两位小数） |
| 3 | 易错点、逆向、生活情境 | 0.25 × 0.4（位数不够要补 0） |

每个知识点的三道题**按 1/2/3 各一道**配，这样以后可以按她当前水平挑难度：
连对两天的知识点只出难度 3，错过的从难度 1 重来。

### 跨知识点题

`知识点` 是数组，综合题填多个。现在有 3 道示例（如「长 a 米宽 2.5 米，a=3.2 时面积多少」同时考小数乘法和用字母表示数）。

题号用 `Q-M-MIX-n`，不占用单个知识点的序号。

## 加题规范

> 现存的 127 道是一次性批量生成的。之后补题请直接改 `题库.json`（它才是唯一数据源），
> 不要另写生成脚本再整体覆盖——会把你手改的部分冲掉。

1. **直接改 `题库.json`** —— 这是唯一数据源，不要另写生成脚本再覆盖它（会丢改动）。
2. 题号规则：`Q-<知识点id>-<序号>`，序号从 1 开始，在**同一个知识点内**递增。
3. 选择题的 `答案` 写**下标**（0 = A）。手填容易错，写完一定要看一遍 `选项[答案]` 是不是你想的那个。
4. `解析` 必须写**方法**，不是只报答案。孩子看的是这个。
5. `提示` 是她答错第一次时给的台阶，不能直接给答案。
6. 加完跑一次校验：

```bash
python 大纲题库/check.py
```

它会检查：id 重复、知识点是否存在、难度是否 1–3、选择题答案下标是否越界、有没有漏解析、每个知识点是否够 3 题。

## 以后怎么用

- **先只出题，不急着上线**。等接入做题之后再累积数据。
- 有了作答数据后，按知识点正确率决定：连对 → 只出难度 3；错 1 次 → 难度 2 重来；连错 → 回到难度 1。
- 跨知识点题放在每组最后一题，作为「综合检测」，不参与日常难度调节。
