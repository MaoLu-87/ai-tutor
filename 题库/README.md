# 题库 · 说明

> 三科共用。**错题库是病因，题库是药**——这个目录放"药"和"病历归档"。

---

## 一、目录里有什么

| 文件 | 是什么 | 谁维护 |
| --- | --- | --- |
| `variants.json` | **变式题**（由错题派生，可增可删） | 手改 |
| `attempts.json` | **作答记录**（每次练习/考试一行） | 系统追加，不手改历史 |
| `index.json` | 三科统一索引（错题 + 变式） | `build.py` 生成 |
| `due.json` | 今天该复测哪些错题 | `lifecycle.py` 生成 |
| `build.py` | 汇总索引 + 生成刷题题库 | — |
| `lifecycle.py` | 算复习排期，输出今日待练 | — |

---

## 二、一条数据怎么流

```
错题照片 → 数学错题库/错题库.json（病因，只增不改）
                    ↓ build.py
            题库/index.json（统一索引）
                    ↓
        题库/variants.json（派生变式，药）
                    ↓ build.py
        刷题/drill-bank.json（生成物）
                    ↓ make_drill.py
              线上刷题页
                    ↓ 作答
        attempts.json ＋ 云数据库 drill_submissions
                    ↓ lifecycle.py
              due.json（明天练哪几题）
```

**关键规矩：`drill-bank.json`、`index.json`、`due.json` 都是生成物，永远不要手改。** 要改题改 `variants.json`，要改记录改 `attempts.json`。

---

## 三、每天怎么用

```bash
# 早上看一眼今天该练什么
python 题库/lifecycle.py

# 按到期错题出 8 道题
cd 刷题 && python make_drill.py --due --n 8

# 发布（链接不变）
# 交给 agent 执行 workbuddy_sites_deploy
```

`--due` 的意思是：只从"今天该复测的错题"派生的变式里抽题。等某些题被标成"已巩固"，它们就不会再出现。

## 四、怎么加题

**加变式题**：编辑 `variants.json`，按现有格式追加一条。

```json
{
  "id": "V-009-03",
  "from": "M5A-009",              // 派生自哪道错题（必须真实存在）
  "subject": "数",
  "unit": "U1",
  "kps": ["小数乘法", "小数点定位"],
  "type": "number",                // choice 或 number
  "difficulty": 2,
  "stem": "题干",
  "options": ["A", "B", "C", "D"], // 仅 choice，答案填索引 0-3
  "answer": 0.84,                  // number 填数值
  "hint": "第一次答错时的一句话提示（给方向，不给答案）",
  "explain": "第二次答错时的完整解析：正确答案 + 为什么 + 常见错法"
}
```

**加完必须跑一次 `python 题库/build.py`**，否则刷题页看不到新题。

## 五、出题配比（2026-11-08 v2）

每日两组、每组 9 题，配比由 `make_week.py` 算：

```
科目题数 = round(18 × (100 − 该科知识点评分)/100 ÷ Σ)
知识点权重 = 1 + (1 − 该知识点评分/100) × 2
```

- 近 7 天做过的题排后，优先没做过的
- 每个知识点各自维护游标，跨天轮转
- 详情见根目录 `出卷规范.md` 第二、三节

## 六、淘汰规则（写死在规范里，靠 `lifecycle.py` 执行）

| 环节 | 规则 |
| --- | --- |
| 扩充 | 每道新错题至少派生 2 道变式；每个知识点保底 3 道 |
| 淘汰 | 连续 2 次复测一次答对 → 标 `mastered`，30 天后移出刷题池 |
| 休眠 | 超 60 天没被抽到且所属知识点得分率 > 90% → 移出 |
| 复活 | 淘汰不删，标 `retired`；知识点回潮时重新激活 |

## 用时调节（pace.py，2026-11-08 定）

一组的标准是 **15 分钟 / 9 题 = 每题 100 秒**。做完一组的实际用时会被记进 `题库/pace.json`，
下一轮排题时按它调题量和挑战度：

| 情况 | 题数 | 抽题偏向 |
|---|---|---|
| 每题 > 125 秒 且 正确率 ≥ 80% | 减到 15 分钟装得下的量（6–12，一次最多动 2 题） | 已掌握（先提速度） |
| 每题 > 125 秒 且 正确率 < 80% | 同上，减得更狠 | 已掌握（先保信心） |
| 每题 100–125 秒 | 小幅减 | 已掌握 |
| 每题 85–100 秒 | 不动 | 薄弱点 |
| 每题 65–85 秒 且 正确率 ≥ 85% | 加 | 薄弱点 |
| 每题 65–85 秒 但 正确率 < 85% | **不动**（是粗心，不是题简单） | 薄弱点 |
| 每题 < 65 秒 且 正确率 ≥ 90% | 加到上限 12 | 薄弱点 |

用法：
```bash
python 题库/pace.py --add 2026-11-08:1:9:1120:7   # 日期:第几组:题数:用时秒:答对题数
python 题库/pace.py --sync 云端导出.json           # 批量（字段 drill_date/total/duration_sec/score）
python 题库/pace.py --show                         # 只看账本与建议
python 题库/pace.py --reset                        # 清空（测试后务必执行）
python 刷题/make_week.py --rebalance               # 保留今天，从明天起按新节奏重排
```

注意：
- 题量调节是**渐进**的，一次最多 ±2 题，避免忽上忽下。
- 「难度」不用题库的 `difficulty` 标签（35 道里 31 道都是 2，区分度不够），
  用**知识点掌握度**做代理：偏向「已掌握」= 抽分高的，偏向「薄弱」= 抽分低的。
- 测试完一定要 `--reset` 再重跑 `make_week.py`，否则假数据会污染排期（踩过）。

## 公式参数（tuning.json，2026-11-09）

线上（网页）和本地（脚本）共用 `题库/tuning.json` 一份参数，两边都读它：

| 段 | 管什么 | 谁在用 |
|---|---|---|
| 评分 | 答对逼近、答错折损、月度衰减、起点分、单日单科限幅 | `知识库/score.py`、`engine.js` |
| 打卡 | 每场最少题数、单日星数上限、全对奖励 | `题库/checkin.py`、`engine.js` |
| 节奏 | 目标秒、题数区间、单次变动、各档阈值 | `题库/pace.py`、`engine.js` |
| 抽题 | 科目权重下限、知识点权重系数、近期降权天数 | `刷题/make_week.py`、`engine.js` |

改完跑 `python 网站/build_site.py` 再发布就生效，**不用动代码**。
浏览器端通过 `DB.tuning`（构建时注入 `assets/db.js`）读到同一份参数。

优先级：代码里的默认值只在 tuning.json 缺字段时兜底，正常情况以文件为准。
